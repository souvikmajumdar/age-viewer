# AGE Viewer — Laptop Migration Guide

This guide moves the project to a new machine and gets you back to exactly where
you are in the modernization (currently: **Phase 6e — frontend components → TypeScript**).

---

## What gets packaged

The `scripts/migrate-package.sh` script produces two files:

| File | Purpose |
|------|---------|
| `age-viewer-<timestamp>.zip` | The full working tree (source, manifests, `.kiro/` memory & docs, `.git/`), minus regenerable artifacts. |
| `age-viewer.bundle` | A git bundle (full history, all branches) — a portable backup of git state. |

### Included
- **Source:** `backend/src`, `backend/sql`, `backend/test`, `backend/misc`, `frontend/src`, `frontend/public`, `frontend/index.html`, `e2e/`, `scripts/`
- **Manifests & config:** all `package.json` + `package-lock.json` (root/backend/frontend), `tsconfig*.json`, `vite.config.js`, `vitest.config.js`, `eslint.config.js`, `.prettierrc`, `.prettierignore`, `playwright.config.js`, `ecosystem.config.js`, `Dockerfile`, `.dockerignore`, `.env.example`, `.gitattributes`, `.gitignore`, `.asf.yaml`
- **Docs:** `README.md`, `LICENSE`, `NOTICE`, `DISCLAIMER`
- **Editor:** `.vscode/settings.json`
- **Kiro memory:** `.kiro/steering/`, `.kiro/docs/`
- **Git:** full `.git/` history + your committed WIP checkpoint

### Excluded (recreated on the new laptop)
- `node_modules/` (root, backend, frontend) → `npm run setup`
- `frontend/build/` → `npm run build-front`
- `backend/coverage/`, `playwright-report/`, `test-results/` → regenerated by tests
- `backend/logs/` → runtime logs
- `frontend/src/conf/config.js` → generated, gitignored

> **Secrets note:** No live `.env` exists in the repo today (only `.env.example`).
> If you keep a real `.env` outside the repo, copy it separately and securely — it is
> intentionally NOT in the zip.

## On the OLD laptop

```bash
cd /Users/souvikmajumdar/ibm/kiro/age-viewer
./scripts/migrate-package.sh
```

This commits your in-progress TypeScript work as a checkpoint, then creates the zip
and bundle in a timestamped folder under `$TMPDIR` (path is printed at the end).
Copy **both** files to the new laptop (AirDrop, USB, or secure transfer).

## On the NEW laptop

### 1. Install prerequisites
- **Node.js >= 24.0.0** — https://nodejs.org/ (or `nvm install 24 && nvm use 24`)
- **Docker** or **Podman** — for the PostgreSQL + Apache AGE database
- **git**

Verify:
```bash
node -v   # >= v24.0.0
npm -v
git --version
docker --version   # or: podman --version
```

### 2. Unzip the project
```bash
mkdir -p ~/ibm/kiro
cd ~/ibm/kiro
unzip ~/Downloads/age-viewer-<timestamp>.zip
cd age-viewer
```

### 3. Verify git state is intact
```bash
git status
git log --oneline -5
git branch
```
You should be on `feature/phase-6e-frontend-components-ts` with the WIP checkpoint
commit at the top.

> **If the working tree didn't transfer cleanly**, restore from the bundle instead:
> ```bash
> git clone /path/to/age-viewer.bundle age-viewer-restored
> cd age-viewer-restored
> git checkout feature/phase-6e-frontend-components-ts
> ```

### 4. (Optional) Undo the WIP checkpoint commit
If you'd rather keep that work uncommitted again, like it was before packaging:
```bash
git reset --soft HEAD~1
```

### 5. Install dependencies (recreates node_modules)
```bash
npm run setup
```
Installs root, backend, and frontend dependencies from the lockfiles.

### 6. Set up the database
```bash
docker pull apache/age:latest
docker run -d --name age-viewer-db -p 5455:5432 \
  -e POSTGRES_USER=ageviewer -e POSTGRES_PASSWORD=ageviewer_pw \
  -e POSTGRES_DB=ageviewer apache/age:latest
docker exec age-viewer-db pg_isready -U ageviewer -d ageviewer
docker exec age-viewer-db psql -U ageviewer -d ageviewer -c "CREATE EXTENSION IF NOT EXISTS age;"
```
(Use `podman` equivalents if you prefer Podman — see `README.md`.)

### 7. (Only if running E2E tests) recreate `.env`
```bash
cp .env.example .env
# edit .env and set E2E_DB_PASSWORD and any other values
```

### 8. Start the app
```bash
npm run start
```
Backend → port 3001, frontend → port 3000. Open http://localhost:3000.

### 9. Sanity checks
```bash
npm run lint
cd backend && npm test
cd ../frontend && npm test
```

### 10. Reconnect git to the remote (if you use one)
```bash
git remote -v
# if missing:
# git remote add origin <your-remote-url>
git fetch origin
```

## You're back where you left off when
- `git status` shows branch `feature/phase-6e-frontend-components-ts`
- The `.jsx → .tsx` component migration files are present
- `npm run start` serves the app and you can connect to the AGE database
- `.kiro/steering/` and `.kiro/docs/` are present so Kiro has full project context
